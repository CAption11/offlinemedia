================================================================================
PROJECT STRUCTURE DECISION
================================================================================

OfflineMedia is divided into two operational sections:

1. MAINLOAD - downloadable/local Windows application.
2. PORTABLE - Google Colab/GPU development and real-generation environment.

They share the generation core. Portable is the laboratory used to prove real
AI generation before Mainload presents that generation as an end-user feature.

AI ORCHESTRATION DECISION
================================================================================

The repository already contains .github/workflows/ai-orchestration.yml and
AI_ORCHESTRATION_SETUP.md. Claude's GitHub trigger is confirmed operational by
the user.

The agreed coordination method is the simple "check" model:
- Neither AI is assumed to run continuously in the background.
- GitHub is the shared source of truth.
- Claude updates CLAUDE_WORK.txt when Claude finishes.
- ChatGPT updates CHATGPT_WORK_LOG.txt when ChatGPT finishes.
- The user can simply send "check" when returning.
- ChatGPT then inspects AI_HANDOFF_STATUS.txt, both work logs and recent commits
  and determines whether Claude has finished, without requiring the user to
  explain what Claude did.

AI_HANDOFF_STATUS.txt was added to make the handoff state explicit.

Its fields are:
CURRENT_AGENT
STATUS
TASK
NEXT_AGENT
LAST_COMMIT

Supported status values:
WORKING, READY, REVIEW, BLOCKED, FAILED, IDLE

When ChatGPT finishes:
- update CHATGPT_WORK_LOG.txt
- set CURRENT_AGENT=CLAUDE
- set NEXT_AGENT=CLAUDE
- set STATUS=READY or REVIEW
- record the final commit SHA

When Claude finishes:
- update CLAUDE_WORK.txt
- set CURRENT_AGENT=CHATGPT
- set NEXT_AGENT=CHATGPT
- set STATUS=READY or REVIEW
- record the final commit SHA

Important: the status file is coordination state. It does not itself wake an AI.
