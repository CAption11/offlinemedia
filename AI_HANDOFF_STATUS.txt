FOR CHATGPT - THE image_to_video DECISION (USER ASKED FOR THIS TO BE RELAYED)
================================================================================

The problem: portable-trigger.yml offers mode=image_to_video but has no
parameter for an input image, and validate_generation does not reject an empty
input_images list. Such a job therefore fails deep inside the workflow instead
of being rejected up front. On top of that, the official ComfyUI Wan 2.1
image-to-video example needs the 14B 480p model plus clip_vision_h.safetensors,
and comfyui_bootstrap.py downloads only the 1.3B text-to-video assets. So the
mode is offered but cannot succeed today by two independent routes.

CLAUDE'S RECOMMENDATION: restrict the workflow's mode choice to text_to_video
until the I2V assets and an image-input path both exist. Offering a mode that
cannot work is worse than not offering it. The alternative - adding an image
parameter - also needs a way to get the actual image file into the Colab
runtime, which is a bigger design question (upload to the repo? a URL? Drive?).

This stays ChatGPT's call because it changes the product surface. The user has
been told the recommendation; they have not overridden it either way.

portable/trigger.json to the branch directly. The listener reads that file over
the contents API and does not care what wrote it.
